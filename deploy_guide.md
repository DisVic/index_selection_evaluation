# Руководство по развертыванию БД TPC-DS (Kimball, Inmon, Data Vault)

Данное руководство описывает пошаговый процесс развертывания базы данных TPC-DS с применением трех парадигм моделирования: Kimball (Снежинка/Звезда), Inmon (3NF) и Data Vault 2.0.

## 1. Подготовка окружения

Убедитесь, что у вас установлены:
- **Docker** и **Docker Compose** (для запуска PostgreSQL).
- **Python 3.10+** (для скриптов адаптации).
- **psql** (клиент PostgreSQL для выполнения SQL-скриптов).
- Сгенерированные данные TPC-DS в директории `tpcds_data_1` (или архив `tpcds_data_1.zip` в корне проекта).

## 1.5. Распаковка данных (Опционально)
Скрипты автоматического развертывания сами проверяют наличие папки `tpcds_data_1` и при необходимости автоматически распаковывают архив `tpcds_data_1.zip` (через `unzip` в Linux или `powershell Expand-Archive` в Windows). Если вы делаете это вручную, распакуйте архив в корень проекта, чтобы появилась директория `tpcds_data_1` с `.dat` файлами внутри.

## 2. Запуск СУБД

Мы используем PostgreSQL. Для запуска локального экземпляра используется `docker-compose.yml`:
```bash
docker-compose up -d
```
*Подсказка:* Убедитесь, что порт 5432 свободен на вашей машине.

## 3. Развертывание базовой схемы Kimball (Оригинал TPC-DS)

Схема Kimball строится в схеме `public` по умолчанию.
1. Создайте DDL структур таблиц оригинального `tpcds`:
```bash
psql -h localhost -U tpcds -d tpcds -f tpcds-kit/tools/tpcds.sql
```
*Пароль по умолчанию:* `tpcds_password`

2. Загрузите сгенерированные данные (1.3 ГБ) в базу. Для этого используется подготовленный скрипт `load_data.sql` (который содержит команды `COPY` для каждого `.dat` файла):
```bash
psql -h localhost -U tpcds -d tpcds -f load_data.sql
```
*Особенности загрузки:* В TPC-DS генераторе (`dsdgen`) строки оканчиваются разделителем `|`, из-за чего в конце строк при импорте может ожидаться дополнительная пустая колонка, если генератор работал со стандартными настройками. Следите за целостностью файлов и форматом выгрузки.

## 4. Развертывание Inmon (3NF)

Парадигма Inmon подразумевает денормализацию иерархий измерений.
1. Примените DDL схемы Inmon (создается схема `tpcds_inmon`):
```bash
psql -h localhost -U tpcds -d tpcds -f create_inmon_ddl.sql
```
2. Выполните ELT процесс переноса данных из Kimball в Inmon:
```bash
psql -h localhost -U tpcds -d tpcds -f create_inmon_etl.sql
```

## 5. Развертывание Data Vault 2.0

Data Vault разделяется на Хабы, Линки и Сателлиты.
1. Примените DDL схемы Data Vault (создается схема `tpcds_dv`):
```bash
psql -h localhost -U tpcds -d tpcds -f dv_ddl.sql
```
2. Выполните ELT процесс наполнения DV. Сателлиты используют тип `JSONB` для хранения динамических полезных нагрузок (payloads):
```bash
psql -h localhost -U tpcds -d tpcds -f dv_etl.sql
```

## 6. Известные особенности, решения ошибок и подсказки

### Особенности Data Vault и узкие места
- **Узкое место:** В DV сателлиты были реализованы через колонку `payload JSONB`. Это позволяет в будущем менять структуру "на лету" без `ALTER TABLE`. 
- **Потенциальная проблема:** Хотя загрузка через ELT работает отлично, стандартные средства оптимизаторов БД могут очень сильно проседать при попытках фильтрации и джоинов в многомерных запросах, так как им трудно строить гистограммы по вложенным JSON-ключам. Если в дальнейшем потребуется адаптировать аналитические запросы, может потребоваться создавать "плоские" представления (Views) или материализованные CTE-слои над сателлитами.

### Ошибки форматов (Trailing Pipes) при импорте
- **Ошибка:** При `COPY ... FROM` загрузке Kimball таблиц PostgreSQL мог ругаться на несовпадение количества столбцов `Extra data after last expected column`.
- **Решение:** Это классическая проблема `dsdgen`, который генерирует данные формата `.dat` с пайпом `|` в самом конце строки. Мы учитываем это при загрузке.

### Автоматизация многотомных архивов
Сырые данные (Папка `tpcds_data_1`) могут быть залиты на GitHub только будучи разбитыми на архивы по <100 МБ (например, `.z01`, `.z02` `...`). Скрипты `deploy.bat` и `deploy.sh` настроены на автоматическую поддержку `tpcds_data_1.zip` при наличии стороннего архиватора как `7z` или `unzip`.
